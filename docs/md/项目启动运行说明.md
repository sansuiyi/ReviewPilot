## 0. 一分钟最快验证

**一键方式（推荐，Windows）**：仓库根目录执行 `.\start.ps1`（或双击 `start.bat`）。脚本会自动检查/创建虚拟环境、按需从模板生成 `.secrets.toml`、打印当前模型与密钥状态，然后对示例 diff 跑一次真实 Agent 评审并输出 FINAL REVIEW / TRAJECTORY / STATS。附加模式：`.\start.ps1 -Test` 跑单元测试；`.\start.ps1 -CheckOnly` 仅检查环境。

手动方式：已配置好密钥的前提下，最短链路如下（PowerShell，仓库根目录）：

```powershell
# 1) 安装依赖（需 uv >= 0.12.10）
uv sync

# 2) 配置密钥（首次）
Copy-Item pr_agent/settings/.secrets_template.toml pr_agent/settings/.secrets.toml
# 编辑 .secrets.toml，填写模型对应的 provider key（如 [deepseek] key）

# 3) 跑一次审查
$env:PYTHONPATH='.'
uv run pr-agent --pr_url=https://github.com/<owner>/<repo>/pull/<n> review
```

若本机 `uv` 版本过低（`uv --version` < 0.12.10），见 [§7.1](#71-uv-版本不满足-01210)。

## 2. 安装依赖

### 2.1 标准方式（推荐）

```powershell
uv sync
```

`uv sync` 会按 `uv.lock` 安装运行时依赖 + `dev` 依赖组（含 `pytest`、`ruff`、`pre-commit`，并附带 `pr-agent[all]` 的 provider SDK）。

如只需部分平台 SDK：

```powershell
uv sync --extra github          # 仅 GitHub
uv sync --extra gitlab          # 仅 GitLab
uv sync --extra all             # 全部平台（github/gitlab/bitbucket/azure/codecommit/gitea/google/mosaico）
```

可选能力：

```powershell
uv sync --extra langchain       # LangChain handler
uv sync --group similar-issue   # /similar_issue 向量检索依赖
uv sync --extra otel-grpc       # OTLP/gRPC 链路
```

### 2.2 已有 `.venv` 的离线/受限环境

仓库根目录若已存在 `.venv` 且依赖齐全，可直接用解释器，无需 `uv`：

```powershell
$env:PYTHONPATH='.'
.venv\Scripts\python.exe -m pytest tests/unittest/agent_exec -q
.venv\Scripts\python.exe -m pr_agent.cli --help
```

> 注意：直接用系统 Python 通常缺 `dynaconf` 等依赖，会报 `ModuleNotFoundError: dynaconf`，必须使用项目虚拟环境。

## 3. 密钥与配置

### 3.1 密钥文件（推荐）

```powershell
Copy-Item pr_agent/settings/.secrets_template.toml pr_agent/settings/.secrets.toml
```

最小可运行配置：

```toml
[openai]
key = "sk-..."

[github]
deployment_type = "user"
user_token = "ghp_..."      # 需要 repo 权限
```

常用平台补充：

```toml
[gitlab]
personal_access_token = "glpat-..."
shared_secret = "<webhook secret>"

[gitea]
personal_access_token = "..."
webhook_secret = "..."      # 未设置时 webhook 一律 403

[azure_devops]
org = "<org>"
pat = "<pat>"

[bitbucket]
base_url = "https://<your-host>"
bearer_token = "..."

[bitbucket_server]
bearer_token = "..."
webhook_secret = "..."
```

> **不要提交 `.secrets.toml`**。生产环境用环境变量或 AWS/GCP Secret Provider。

### 3.2 环境变量方式

配置系统为 Dynaconf，加载 `dynaconf.loaders.env_loader` 且 `envvar_prefix=False`，嵌套层级用双下划线 `__`：

```powershell
$env:OPENAI__KEY       = "sk-..."
$env:GITHUB__USER_TOKEN = "ghp_..."
$env:CONFIG__MODEL     = "gpt-5.6"
$env:CONFIG__GIT_PROVIDER = "github"
$env:AGENT_EXEC__ENABLED  = "true"     # 开启 Agent 循环
```

优先级：环境变量 > `.secrets.toml` > `configuration.toml` 默认值 > 仓库 `.pr_agent.toml`（仅在对应命令下由 `apply_repo_settings` 合并）。

### 3.3 选择模型

默认在 `pr_agent/settings/configuration.toml`：

```toml
[config]
model = "gpt-5.6"
fallback_models = ["gpt-5.6-terra"]
```

火山方舟（OpenAI 兼容，走 LiteLLM）：

```toml
[config]
model = "volcengine/doubao-seed-1-6-250615"
```

并在 `.secrets.toml` 增加：

```toml
[volcengine]
key = "<your-ark-api-key>"
# api_base = "https://ark.cn-beijing.volces.com/api/v3"   # 可选
```

`run_agent.py` 会自动把该 key 注入 `VOLCENGINE_API_KEY` / `ARK_API_KEY`。

> 仓库级覆盖：在**被审查仓库**的根目录放 `.pr_agent.toml`，例如
> ```toml
> [config]
> model = "volcengine/doubao-seed-1-6-250615"
> [agent_exec]
> enabled = true
> ```
> 本仓库根目录的 `.pr_agent.toml` 是给 Qodo 托管机器人用的（含 `[review_agent]`、`/agentic_review`），**开源版不读取这些键**；本地 Agent 请用 `[agent_exec]`。

## 4. 运行形态

### 4.1 CLI 单次命令（最常用）

```powershell
uv run pr-agent --pr_url=<PR_URL> review
```

支持的命令（`command2class`）：

| 命令 | 说明 |
|---|---|
| `review` / `review_pr` / `auto_review` | PR 审查 |
| `describe` / `describe_pr` | 生成 PR 描述 |
| `improve` / `improve_code` | 代码改进建议 |
| `ask "问题"` / `ask_question` | 针对 PR 提问 |
| `ask_line` | 行级提问 |
| `update_changelog` | 更新 CHANGELOG |
| `config` / `settings` | 打印当前配置 |
| `help` | 帮助信息 |
| `similar_issue` | 相似 issue 检索（需 `--group similar-issue`） |
| `add_docs` | 补充文档建议 |
| `generate_labels` | 生成标签 |

参数示例：

```powershell
# 追加指令
uv run pr-agent --pr_url=<URL> review --pr_reviewer.extra_instructions="重点看并发安全"

# 本地纯 diff 模式（无需 PR，不发布评论）
uv run pr-agent --diff-file=changes.patch review
uv run pr-agent --stdin review < changes.patch
uv run pr-agent --diff-file=changes.patch --output=result.md review
uv run pr-agent --diff-file=changes.patch --json-output=result.json review
```

> `--output` / `--json-output` 仅支持 plain-diff 模式（`--stdin` 或 `--diff-file`），且必须写在命令之前。`--stdin` 与 `--diff-file` 互斥。

### 4.2 启用自研 Agent 循环（ReviewPilot agent_exec）

默认关闭，`/review` 走原有单次管线。开启方式（三选一）：

```toml
# a) 仓库根目录 .pr_agent.toml
[agent_exec]
enabled = true
max_steps = 6
max_tool_calls = 4
max_tokens = 20000
tool_timeout_seconds = 10.0
verify_confidence_threshold = 0.6
loop_detection_window = 3
enforce_tool_whitelist = true
```

```powershell
# b) 环境变量
$env:AGENT_EXEC__ENABLED = "true"

# c) 直接改 pr_agent/settings/configuration.toml 的 [agent_exec] enabled = true
```

开启后 `/review` 的行为：

```
PRReviewer.run()
  └─ if [agent_exec].enabled and 有 diff 文件:
         ReviewAgentRunner.run(diff_files)
         → 发布 final_answer → return
     否则：沿用原单次审查管线（零改动）
```

Agent 内部图（LangGraph）：

```
orient → review → { tools | verify | finalize } → orient ...
```

- `orient`：确定性环境摘要（步数/工具预算/已有 findings），不调模型
- `review`：模型输出决策 JSON（tools / verify / finalize）+ 服务端护栏
- `tools`：白名单工具执行（超时、审计事件）
- `verify`：独立 LLM 复核（Jev 规则）
- `finalize`：汇总输出

### 4.3 独立跑 Agent（不经过 PR，示例脚本）

```powershell
$env:PYTHONPATH='.'
uv run python run_agent.py
```

`run_agent.py` 会构造一个示例 Python diff（含 `os.system`），用 `ReviewAgentRunner` 跑完整循环，并打印：

```
===== FINAL REVIEW =====
===== TRAJECTORY =====
===== STATS =====
```

适合联调模型连通性与工具链路，不发布任何评论。

### 4.4 Webhook 服务

各服务都有 `if __name__ == "__main__": start()`，本地启动：

```powershell
uv run python -m pr_agent.servers.github_app
uv run python -m pr_agent.servers.gitlab_webhook
uv run python -m pr_agent.servers.gitea_app
uv run python -m pr_agent.servers.bitbucket_app
uv run python -m pr_agent.servers.bitbucket_server_webhook
uv run python -m pr_agent.servers.azuredevops_server_webhook
uv run python -m pr_agent.servers.gerrit_server
uv run python -m pr_agent.servers.github_polling      # 轮询模式，无需公网回调
```

- 端口：gunicorn `bind = 0.0.0.0:${PORT:-3000}` → 默认 **3000**，可用 `PORT` 覆盖。
- Worker 数：`GUNICORN_WORKERS`（不设则按 cgroup 内存自动计算并设上限）。
- 必需密钥（缺则直接 403/启动失败）：
  - GitHub App：`[github] app_id`、`private_key`、`webhook_secret`
  - GitLab：`[gitlab] shared_secret`
  - Gitea / Bitbucket Server / Azure DevOps Server：对应 `webhook_secret` / `webhook_username`+`webhook_password`
- 健康检查与 Prometheus：`[otel] exporter_type = "prometheus"` 时暴露 `GET /metrics`。

## 6. Benchmark 评测（Precision / Recall / 加权评分）

Benchmark 是库，不是 CLI 子命令。数据集为 JSON：

```json
[
  {
    "id": "pr-001",
    "diff_files": [
      {"filename": "a.py", "patch": "diff --git ...\n+os.system(cmd)\n", "language": "python"}
    ],
    "ground_truth": [
      {"file_path": "a.py", "line_number": 2, "title": "command injection", "risk_level": "high"}
    ]
  }
]
```

运行脚本：

```python
# benchmark_run.py（仓库根目录）
import asyncio
from pr_agent.agent_exec.benchmark import BenchmarkRunner, ScoringWeights, load_dataset
from pr_agent.agent_exec.runner import ReviewAgentRunner

async def main():
    items = load_dataset("benchmark/prs.json")
    weights = ScoringWeights(precision=0.4, recall=0.4, completion=0.2)
    report = await BenchmarkRunner(runner_factory=ReviewAgentRunner, weights=weights).run(items)
    print(report.as_dict())
    for r in report.per_item:
        print(r.item_id, "completed=", r.completed, "tools=", r.tool_calls, "steps=", r.steps)

asyncio.run(main())
```

```powershell
$env:PYTHONPATH='.'
uv run python benchmark_run.py
```

输出字段：

| 字段 | 含义 |
|---|---|
| `precision` | 命中 ground-truth 的 finding / 报告的全部 finding |
| `recall` | 命中 ground-truth 的 finding / ground-truth 总数 |
| `completion_rate` | 产生非空 final_answer 的 PR 占比 |
| `avg_tool_calls` | 平均工具调用次数 |
| `avg_steps` | 平均步数 |
| `avg_tokens` | 平均 token 估算 |
| `weighted_score` | `precision*w_p + recall*w_r + completion*w_c`（按权重归一） |

匹配规则：`file_path` 相同 + `line_number` 相同 + 标题 token Jaccard ≥ 0.5。

多 Sub-agent 评测：

```python
from pr_agent.agent_exec.federation import ReviewerFederation
findings = await ReviewerFederation().review(diff_files, max_files_per_batch=1)
```

## 7. 常见问题

### 7.1 uv 版本不满足 0.12.10

现象：

```
error: Required uv version `>=0.12.10` does not match the running version `0.10.9`.
```

处理（任选其一）：

```powershell
uv self update                 # 能访问 GitHub 时
winget upgrade astral-sh.uv    # 或 Windows 包管理器
pip install -U uv              # 或 pip 升级
```

若更新受限（如 GitHub API rate limit），直接用已有虚拟环境：

```powershell
$env:PYTHONPATH='.'
.venv\Scripts\python.exe -m pytest tests/unittest/agent_exec -q
```

### 7.2 `ModuleNotFoundError: dynaconf`

说明用错了解释器。改用 `.venv\Scripts\python.exe`，或先执行 `uv sync`。

### 7.3 提示 `settings_prod/.secrets.toml` 不存在

```
WARNING | custom_merge_loader:load - Settings file not found: pr_agent/settings_prod/.secrets.toml. Skipping it.
```

属正常告警，该文件用于生产密钥，本地可不创建。

### 7.4 webhook 返回 403

对应平台的 `webhook_secret` 未设置或与平台侧不一致（GitLab/Gitea/Bitbucket Server/Azure DevOps Server 均强制校验）。

### 7.5 模型连通失败

- 确认 `config.model` 与密钥 provider 匹配（如 `volcengine/...` 必须配火山 key）。
- 确认 `OPENAI__KEY` / `[openai] key` 已生效：`uv run pr-agent --pr_url=... config` 可打印当前配置（注意脱敏）。
- 关注 `fallback_models` 是否被触发，日志关键字 `FallbackEligibleError`。

### 7.6 Agent 没生效

- 确认 `[agent_exec] enabled = true` 或 `AGENT_EXEC__ENABLED=true`。
- 确认 PR 有 diff 文件（空 diff 会回退到原管线）。
- 确认 `config.model` 可用；Agent 复用 `LiteLLMAIHandler`。
- 查看日志中的 `ReviewAgentRunner` / decision JSON。

### 7.7 Agent 一直 verify / 步数耗尽

`max_steps` 与 `max_tool_calls` 是**服务端强制**的硬上限。若发现反复 verify，检查：
- `verify_confidence_threshold`（默认 0.6）是否过高导致大量 finding 被要求复核；
- 模型是否稳定返回 `action` 字段（解析失败会直接 finalize）；
- `loop_detection_window`（默认 3）是否触发强制收尾。

## 8. 配置速查

| 配置 | 位置 | 默认 | 说明 |
|---|---|---|---|
| `config.model` | `configuration.toml` | `gpt-5.6` | 主模型 |
| `config.git_provider` | 同上 | `github` | `github`/`gitlab`/`gitea`/`bitbucket`/`azure`/`local`/`plain_diff` |
| `config.publish_output` | 同上 | `true` | 是否发布评论 |
| `agent_exec.enabled` | 同上 / `.pr_agent.toml` | `false` | 启用 Agent 循环 |
| `agent_exec.max_steps` | 同上 | `6` | 决策迭代上限 |
| `agent_exec.max_tool_calls` | 同上 | `4` | 单次 PR 工具调用上限 |
| `agent_exec.tool_timeout_seconds` | 同上 | `10.0` | 单工具超时 |
| `agent_exec.verify_confidence_threshold` | 同上 | `0.6` | Jev 复核阈值 |
| `agent_exec.loop_detection_window` | 同上 | `3` | 连续相同决策 N 次强制收尾 |
| `agent_exec.enforce_tool_whitelist` | 同上 | `true` | 拒绝未注册工具 |
